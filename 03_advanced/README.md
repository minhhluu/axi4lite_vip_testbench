# 03 - Advanced: Topologies & Error Handling

## Goal
- **Address Decode**: 1 Master -> 2 Slaves (each master validates R/W to both slaves).

## AXI Response Codes

The AXI protocol defines four possible response codes returned on the **B channel** (write)
and **R channel** (read):

| Code      | Value   | Meaning                                                                 |
|-----------|---------|-------------------------------------------------------------------------|
| `OKAY`    | `2'b00` | Transaction succeeded.                                                  |
| `EXOKAY`  | `2'b01` | Exclusive access succeeded (semaphore/atomic op).                       |
| `SLVERR`  | `2'b10` | Slave was reached but rejected the operation (e.g., write to read-only register). |
| `DECERR`  | `2'b11` | **Decode Error** — no slave mapped at the requested address. Generated by the Interconnect, not the slave. |

---

## Error Response: DECERR

### Root Cause

A `DECERR` (Decode Error) is returned by the **AXI SmartConnect / Interconnect** — not by
any slave — when a master targets an address that falls **outside every slave's mapped
address window**.

In this project, the error was reproduced by writing to address `0x0000_1000`, which is not
mapped in the Vivado Address Editor:

```
// Wrong address — nothing mapped here -> DECERR
localparam xil_axi_ulong MST1_ADDR = 32'h0000_1000;  // FAIL: DECERR (resp = 2'b11)

// Correct address — inside Slave 1's window -> OKAY
localparam xil_axi_ulong MST1_ADDR = 32'h44A0_0000;  // PASS: OKAY  (resp = 2'b00)
```

### How to Observe in Waveform

When a DECERR occurs, the AXI channels behave as follows:

1. **AW channel** — master drives `AWVALID` high with the bad address; interconnect accepts it (`AWREADY`).
2. **W channel** — master drives `WVALID` + `WDATA`; interconnect accepts it (`WREADY`).
3. **B channel** — interconnect drives `BVALID` with `BRESP = 2'b11` (DECERR). No slave ever sees the transaction.

```
Signal          | Normal (OKAY)     | Error (DECERR)
----------------|-------------------|-------------------
M00_AXI_AWADDR  | 0x44A0_0000       | 0x0000_1000  <- bad address
M00_AXI_BRESP   | 2'b00 (OKAY)      | 2'b11 (DECERR)
Slave memory    | Updated           | Unchanged
```

### DECERR vs SLVERR — Key Difference

| Aspect        | DECERR                              | SLVERR                                |
|---------------|-------------------------------------|---------------------------------------|
| **Source**     | Interconnect (SmartConnect)         | Slave peripheral itself               |
| **Cause**      | Address not mapped to any slave     | Slave rejects the operation           |
| **Address**    | Outside all slave windows           | Inside a valid slave window           |
| **Slave sees** | Nothing — transaction never arrives | Full transaction — slave decides      |

## Error Response: SLVERR

### Root Cause

A `SLVERR` (Slave Error, `BRESP = 2'b10`) is returned by the **slave peripheral itself** — the
transaction successfully passed through the interconnect and reached the slave, but the
slave decided to reject it.

Common real-world causes:
- **Writing to a read-only register** (e.g., status register, hardware ID)
- **Accessing an unimplemented offset** within a peripheral's address range
- **Permission violation** (e.g., secure-only register accessed in non-secure mode)
- **Protocol violation** at the slave (e.g., unsupported burst length)

### How It's Implemented in This Testbench

Since the Xilinx AXI VIP **memory model** (`slv_mem_t`) hardcodes `BRESP = OKAY` in its
`fill_wr_reactive()` function — there is no built-in API to change this — we use the
**reactive slave** (`slv_t`) for Slave 2.

The reactive slave does **not** have an automatic memory model. Instead, two `initial`
blocks (`SLV2_WR_HANDLER` and `SLV2_RD_HANDLER`) manually service every transaction:

```systemverilog
// Simplified reactive write handler (runs forever in parallel)
forever begin
    slave_agent2.wr_driver.get_wr_reactive(wr_reactive);
    addr = wr_reactive.get_addr();

    if (addr >= SLV2_RESERVED_ADDR && addr < SLV2_RESERVED_ADDR + 32'h0100) begin
        wr_reactive.set_bresp(XIL_AXI_RESP_SLVERR);
    end else begin
        slv2_mem[addr] = wr_reactive.get_data_beat(0);
        wr_reactive.set_bresp(XIL_AXI_RESP_OKAY);
    end

    wr_reactive.set_response_delay(1);
    slave_agent2.wr_driver.send(wr_reactive);
end
```

### Reserved Address Region

| Address Range                    | Slave Response |
|----------------------------------|----------------|
| `0x44A1_0000 – 0x44A1_0EFF`     | `OKAY`         |
| `0x44A1_0F00 – 0x44A1_0FFF`     | **`SLVERR`**   |
| `0x44A1_1000 – 0x44A1_FFFF`     | `OKAY`         |

### How to Observe in Waveform

When a SLVERR occurs on Slave 2:

1. **AW channel** — interconnect forwards `AWVALID` + `AWADDR = 0x44A1_0F00` to `M01_AXI`. Slave accepts with `AWREADY`.
2. **W channel** — interconnect forwards `WVALID` + `WDATA`. Slave accepts with `WREADY`.
3. **B channel** — slave drives `BVALID` with `BRESP = 2'b10` (**SLVERR**). Data is **not** stored.

```
Signal          | Normal Write      | SLVERR Write
----------------|-------------------|-------------------
M01_AXI_AWADDR  | 0x44A1_0020       | 0x44A1_0F00  <- reserved
M01_AXI_BRESP   | 2'b00 (OKAY)      | 2'b10 (SLVERR)
Slave memory    | Updated           | Unchanged (slave rejected)
```

### Test 5 Validation

The test verifies two things:
1. **SLVERR is received** when writing to the reserved address `0x44A1_0F00`
2. **OKAY still works** — a follow-up normal write confirms the slave hasn't locked up

## Test Scenarios

### TEST 1 — Address Decode: MST1 -> Slave1 & Slave2
Master 1 writes unique data patterns to **both** slaves at distinct addresses, then reads
back and compares expected vs. actual data.

Validates that the SmartConnect correctly decodes `AWADDR`/`ARADDR` and routes each
transaction to the right slave port (`M00_AXI` or `M01_AXI`).

|------|---------------|---------------|-------------------|
| W    | `0x44A0_0000` | `0xAABB_1111` | `OKAY`            |
| W    | `0x44A1_0000` | `0xAABB_2222` | `OKAY`            |

| R    | `0x44A1_0000` | `0xAABB_2222` | `OKAY` + match    |

### TEST 5 — Error Response: SLVERR (Slave 2)
Master 1 writes to a **reserved address** (`0x44A1_0F00`) inside Slave 2's window. The
reactive slave handler detects the reserved range and responds with `SLVERR`.

A follow-up normal write verifies the slave remains operational after the error.
